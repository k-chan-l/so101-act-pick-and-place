# 데이터 확인 기록

롤아웃만 봐서는 알 수 없던 것을 **저장된 데이터를 직접 열어 확인한** 기록입니다. 로봇 없이 다시 해볼 수 있습니다.

```bash
conda activate lerobot
DS=~/.cache/huggingface/lerobot/k-chan-l/pick_and_place5_20260901_154211
```

### 어디에 무엇이 있나

데이터셋은 `~/.cache/huggingface/lerobot/<user>/<name>/`, 정책은 `~/.cache/huggingface/hub/models--<user>--<name>/` 에 있습니다.

| 파일 | 내용 |
| --- | --- |
| `meta/info.json` | 에피소드 수, 프레임 수, 기록된 항목 목록 |
| `meta/stats.json` | 이미지 밝기 평균, 관절값의 최소·최대·중앙값. **데이터셋끼리 비교할 때 여기를 봅니다** |
| `data/**/*.parquet` | 프레임 한 장씩의 기록. 관절값, 그리퍼 열림 정도 등 |
| `videos/` | 에피소드별 `cam_top`·`cam_wrist` 영상 |

## 1. 4차는 왜 무너졌나 — 교정 데이터의 팔 자세 (Round 4)

`meta/stats.json`에서 관절값을 3차와 4차(교정 17개를 더한 것)로 비교했습니다.

| 관절 | 3차 | 교정 데이터를 더한 뒤 |
| --- | ---: | ---: |
| 관절2 최대 | 49.1 | 61.3 |
| 관절3 최소 | −54.0 | −80.4 |
| **관절3 중앙값** | **−3.4** | **−57.6** |
| 관절5 최대 | 36.2 | 54.5 |

프레임을 19%만 더 넣었는데 관절3의 한가운데 값이 54도나 밀렸습니다. 교정 에피소드가 **전부 실패한 상태에서 시작**해서, 홈 자세도 큐브로 다가가는 구간도 한 장면도 없기 때문입니다. → [4차](rounds/round4.md)

같이 확인한 것들:

- 교정 프레임 **6,400개 전부가 사람이 개입한 구간**이었습니다. 정책이 혼자 움직인 장면은 섞이지 않았습니다
- 병합 수치가 맞습니다: 50+17=67 에피소드, 27,147+6,400=33,547 프레임
- 이미지 밝기 평균 차이가 0.01~0.03으로 사실상 같습니다. 카메라 설정이 달라진 게 아닙니다
- 학습 전 숫자 범위를 맞추는 기준값도 병합된 데이터로 다시 계산돼 있었습니다

**즉 데이터를 다루는 과정에는 문제가 없었고, 문제는 교정 데이터 자체의 성격이었습니다.**

## 2. 학습 데이터에 "다시 잡는" 시연이 있었나 (Round 5)

그리퍼가 열렸다 닫히는 것을 세서, 에피소드마다 **몇 번 잡으려 했는지** 셌습니다. 값이 20보다 크면 열림, 8보다 작으면 닫힘으로 봤습니다.

**결과**

| | |
| --- | --- |
| 잡는 동작이 있는 에피소드 | **42개** — 전부 그리퍼를 **정확히 한 번만** 닫음 |
| 잡는 동작이 없는 에피소드 | **8개** (ep 42–49 = 엣지 케이스) |
| 두 번 이상 닫은 에피소드 | **0개** |

**학습 데이터에 다시 잡는 시연이 하나도 없습니다.** "멈칫한 에피소드는 즉시 삭제" 촬영 규칙이 지켜졌다는 뜻이기도 합니다.

→ 5차 평가에서 나온 재시도 행동은 **시연을 따라 한 것이 아닙니다.** → [5차 추론 ⑤](rounds/round5.md)

## 3. 7개 큐브 지점이 데이터에서 구분되나 (Round 5)

각 에피소드에서 **큐브를 처음 집는 순간**의 팔 자세를 뽑아 지점별로 묶었습니다. 지점당 6회를 연속으로 찍었으므로 에피소드 순서가 곧 지점 번호이고, **평가 지점 번호 1~7과 순서가 같음을 운영자가 확인**했습니다.

### 지점별 파지 자세

| 지점 | 시연 수 | 베이스 회전 | 팔 뻗음 | 평가 성공 |
| ---: | ---: | ---: | ---: | ---: |
| 1 | 6 | 78.3 ± 3.8 | 31.6 ± 13.2 | 0/3 |
| 2 | 6 | 77.1 ± 4.0 | 32.1 ± 11.9 | 2/3 |
| 3 | 6 | 72.4 ± 3.4 | 21.5 ± 9.1 | 2/3 |
| 4 | 6 | 72.9 ± 0.9 | 18.3 ± 11.3 | 2/3 |
| 5 | 6 | 68.8 ± 4.1 | 18.8 ± 11.2 | 0/3 |
| 6 | 6 | 70.6 ± 2.8 | 10.5 ± 7.9 | 0/3 |
| 7 | 6 | 65.5 ± 4.1 | 1.1 ± 12.6 | 1/3 |

### 지점 사이 간격보다 지점 안의 흔들림이 더 큽니다

| 관절 | 7지점 전체가 퍼진 폭 | 같은 지점 안에서의 흔들림 |
| --- | ---: | ---: |
| 베이스 회전 | **12.8°** | **±3.3°** |
| 팔 뻗음 | 31.0° | ±11.0° |

- 7개 지점 **전부가 베이스 회전 12.8° 안에** 몰려 있는데, 지점 하나를 여섯 번 찍은 것끼리도 ±3.3°씩 흔들립니다
- 지점 3(72.4±3.4°)과 지점 4(72.9±0.9°)는 베이스 회전각이 **사실상 같습니다**
- 팔 뻗음은 더 심해서, 지점 사이 간격과 지점 안의 흔들림이 거의 같습니다

**옆 지점끼리 자세가 포개져 있습니다.** 정책이 위치를 암기한 것이 아니라, **애초에 구분할 수 없는 데이터였습니다.** → [5차 확인 ②](rounds/round5.md)

### 바깥쪽 지점이 특별히 나쁘지도 않았습니다

"가운데로만 가려는 쏠림"이라면 바깥 지점이 나빠야 하는데, 가장 바깥 두 지점(1과 7)의 성적이 **0/3과 1/3으로 엇갈립니다.** 그런 쏠림으로는 설명되지 않습니다.

## 4. 지점당 3회로 지점별 차이를 판단할 수 있나 (Round 5)

**없습니다.**

성공한 지점(2·3·4)과 전멸한 지점(1·5·6)이 갈렸지만, 지점당 3회는 너무 적습니다. **일곱 지점의 실력이 전부 같아도 3번 중 한 번도 못 하는 지점이 두세 곳 우연히 생기는 수준입니다.**

"지점 1·5·6이 특별히 나쁘다"고 말하려면 **지점당 9회는 해야** 합니다.

> 다만 운영자가 눈으로 본 **"엉뚱한 위치로 이동한다"는 행동 자체**는 성공률 숫자와 별개의 직접 증거입니다. 판단할 수 없는 것은 "지점마다 난이도가 다른가"이지, "위치를 제대로 못 짚는가"가 아닙니다.
