# 4차 — DAgger 교정 데이터 fine-tune (회귀)

| 검증하려는 가설 | DAgger 교정 데이터가 파지 정밀도를 올린다 |

| 근거 | 0/10 회귀. 허공 잡음 재출현 |

---
### 데이터 구성
- 데이터셋: `k-chan-l/pick_and_place4` — **67 에피소드 / 33,547 프레임**
  - 3차 `pick_and_place3` 50ep / 27,147 프레임
  - DAgger 교정 `rollout_pick_and_place3_dagger` **17ep / 6,400 프레임**
- 교정은 `--strategy.record_autonomous=false`(corrections-only)로 수집했습니다. `intervention` 플래그가 **6,400/6,400 전부 True**로, 정책 자율 실행 프레임은 섞이지 않았습니다.
- 병합 시 `intervention` 컬럼을 제거한 `_clean` 사본을 사용했습니다 (3차 데이터에 없는 컬럼이라 스키마를 맞춰야 함).

### 학습
- **3차 체크포인트 `pick_and_place3_act`에서 `--policy.path`로 이어 학습.** from scratch 아님.
- **40,000 steps** / batch_size 16 / **`image_transforms.enable=false`**
- 정책: `k-chan-l/pick_and_place4_act`

> 3차 가중치는 증강 **on**으로 학습된 것인데 4차 fine-tune은 **off**입니다. **데이터 추가와 증강 제거가 동시에** 들어갔습니다 → 4b로 분리.

| 헛집은 뒤 **재파지 시도** (3차엔 없던 행동) | 7 / 10 |
| 재파지로 **파지 성공까지 간 시행** | 2 / 10 |

- **큐브 인식이 거의 되지 않습니다.** 허공 잡음은 1차의 실패 양상입니다.
- 동시에 **재파지라는 새 행동은 확실히 학습됐습니다.** 교정 데이터의 *동작 패턴*은 들어왔는데 *시각적 근거*를 잃었습니다.
- 컵 단계까지 간 시행이 1건(1회차)뿐이라 3차의 컵 문제는 이 라운드에서 검증되지 않았습니다.

### 실패 원인 진단

데이터 처리 자체에는 문제가 없었습니다 — 자율 프레임 미혼입, 병합 수치 일치(50+17=67, 27,147+6,400=33,547), 이미지 RGB 평균 차 0.01~0.03, 정규화 통계 `count=33547`로 재계산됨. 원인은 **교정 데이터의 성질**입니다.

**(a) 상태 분포가 좁은 영역에 뭉쳐 있습니다.** 교정 에피소드는 전부 실패 상태에서 시작하므로 홈 포지션도 초기 접근 구간도 한 프레임도 없습니다. 팔이 이미 큐브 근처로 내려간 자세만 6,400프레임입니다.

| 관절 | 3차 | 병합 후 |
| --- | --- | --- |
| 관절2 최대 | 49.1 | 61.3 |
| 관절3 최소 | −54.0 | −80.4 |
| 관절3 **중앙값** | **−3.4** | **−57.6** |
| 관절5 최대 | 36.2 | 54.5 |

19% 프레임을 추가했는데 관절3 중앙값이 54도 이동했습니다.

**(b) 같은 화면에 서로 다른 동작이 붙어 있습니다.** 그 구간에서 화면은 거의 변하지 않는데(손목캠이 큐브를 계속 봄) 동작은 재시도·더듬기·각도 변경으로 제각각입니다. 사람 시연을 그대로 따라 하도록 훈련된 모델은 여기서 **"이 화면에서는 무슨 동작이 올지 알 수 없다"** 를 배우고, 결국 **동작들의 평균**으로 수렴합니다. 그것이 화면을 무시한 채 평균 궤적만 재생하는 것 = 허공 잡음입니다. 하필 **큐브 바로 앞, 화면을 제일 잘 봐야 할 구간**을 이 뒤죽박죽 데이터가 덮었습니다.

(a)와 (b)는 재파지 행동의 출현과 파지 정밀도 회귀를 **하나의 원인으로** 묶어 설명합니다.

**경합 가설 — 증강 제거.** 3차는 증강 on으로 학습된 가중치인데 4차 fine-tune은 off입니다. 시각적 강건성이 40k steps 동안 좁은 데이터에 과적합되며 무너졌을 수 있습니다. 두 가설은 배타적이지 않으며, 4b가 이를 가릅니다.
